03 / RELATIONAL MODEL

Database Entities & Relationships

Normalized 5-table relational schema enforcing referential integrity

STUDENTS & ADMINS Core Auth

  • PK student_id INT AUTO_INCREMENT
  • name VARCHAR(100) NOT NULL
  • email VARCHAR(150) UNIQUE NOT NULL
  • password_hash VARCHAR(255) NOT NULL, created_at TIMESTAMP
  • ADMINS Table: PK admin_id, username UNIQUE, password_hash

CATEGORIES Lookup Master

  • PK category_id INT AUTO_INCREMENT
  • category_name VARCHAR(100) UNIQUE NOT NULL
  • Pre-seeded Domain Values: Hostel, Academics, Infrastructure, Administration, IT Support
  • Referenced by complaints with ON DELETE RESTRICT.

COMPLAINTS Transactional

  • PK complaint_id INT AUTO_INCREMENT
  • FK student_id references students(student_id) ON DELETE CASCADE
  • FK category_id references categories(category_id) ON DELETE RESTRICT
  • description TEXT NOT NULL
  • status ENUM('Pending','In Progress','Resolved') DEFAULT 'Pending'

ACTION_LOGS Audit Trail

  • PK log_id INT AUTO_INCREMENT
  • FK complaint_id references complaints(complaint_id) ON DELETE CASCADE
  • action_taken VARCHAR(255) NOT NULL
  • log_timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  • Populated automatically via AFTER UPDATE database trigger.
Cardinality: Students (1 : N) Complaints  |  Categories (1 : N) Complaints  |  Complaints (1 : N) Action_Logs 3NF Verified
04 / SCHEMA NORMALIZATION

Relational Integrity & Normal Forms (1NF – 3NF)

Eliminating redundancy, insertion, update, and deletion anomalies

First Normal Form

1NF: Atomic Values

Every column in every table holds indivisible, scalar values with no repeating groups or arrays.

  • Student credentials, complaint text, and category names are stored in separate atomic columns.
  • Each complaint is uniquely identified by complaint_id.
Zero Repeating Groups
Second Normal Form

2NF: Full Dependency

Every non-prime attribute is fully functionally dependent on the entire primary key.

  • complaint_id → {student_id, category_id, description, status, created_at}
  • Single-attribute surrogate primary keys guarantee zero partial dependencies.
Zero Partial Dependencies
Third Normal Form

3NF: No Transitive Keys

No non-prime attribute depends transitively on the primary key.

  • student_id → {name, email} isolated in students.
  • category_id → category_name isolated in categories.
  • Updating a category name updates 1 row instead of hundreds.
Zero Update Anomalies
Referential Actions: ON DELETE CASCADE (Student removal cleans complaints)  •  ON DELETE RESTRICT (Protects active categories)
05 / ADVANCED SQL IMPLEMENTATION

Views, Stored Procedures & Automated Triggers

Database-level encapsulation of complex joins, state transitions, and audit trails

SQL View

v_complaint_details

CREATE VIEW v_complaint_details AS
SELECT c.complaint_id,
       s.name AS student_name,
       s.email,
       cat.category_name,
       c.description, c.status
FROM complaints c
JOIN students s 
  ON c.student_id = s.student_id
JOIN categories cat 
  ON c.category_id = cat.category_id;

Simplifies 3-table inner joins into a virtual table for the Admin Console Registry.

Stored Procedure

sp_resolve_complaint

DELIMITER //
CREATE PROCEDURE sp_resolve_complaint(
    IN p_complaint_id INT
)
BEGIN
    UPDATE complaints
    SET status = 'Resolved'
    WHERE complaint_id = p_complaint_id;
END //
DELIMITER ;

-- C++ Invocation:
CALL sp_resolve_complaint(12);

Encapsulates complaint resolution logic behind a parameterized database routine.

AFTER UPDATE Trigger

trg_after_complaint_resolve

DELIMITER //
CREATE TRIGGER trg_after_complaint_resolve
AFTER UPDATE ON complaints
FOR EACH ROW
BEGIN
  IF OLD.status != 'Resolved' 
     AND NEW.status = 'Resolved' THEN
    INSERT INTO action_logs
      (complaint_id, action_taken)
    VALUES
      (NEW.complaint_id, 'Resolved');
  END IF;
END //

Automatically records an immutable audit entry whenever a complaint is resolved.

Aggregate Reporting Query: SELECT cat.category_name, COUNT(c.complaint_id) FROM categories cat LEFT JOIN complaints c ... GROUP BY cat.category_id;
